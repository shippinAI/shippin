# Review: VM-first tenants (2026-10-16)

Design: docs/architecture/vm-first-tenants.md. Commits 6b93e37..HEAD (this branch of work).

## What changed
- **hostd** (allowlisted, argv only): `place` decides per workspace whether Incus calls go to the host
  project (legacy direct) or into the tenant VM via `incus exec tvm-<t> -- incus --project=ws …`.
  New routes: `GET/POST /tenants/{t}/vm`, `POST /tenants/{t}/vm/{start|stop|restart}`. Provision
  creates the VM for VM-mode tenants (new tenants when `vm_first`), with rollback of what the attempt
  created. Tenant delete removes nested workspaces (edge cleaned even if the guest fails), the VM and
  its data volume. Templates are exported once to `/var/lib/shippin/images/<fp>` and imported into
  each VM on first use.
- **console**: operator `GET/POST /v1/operator/tenants/{id}/vm`, `POST …/vm/{action}`; nested
  workspace states are synced after VM actions (only for the tenant's own workspace rows).
- **web**: tenant VM card in the operator tenant drawer (state, vCPU, memory, workspace storage,
  root disk, nested containers, restart/stop/start, enable-with-confirm for legacy tenants).
- **image**: `deploy/image/build-tenant-vm.sh` → `shippin/tenant-vm` (Debian 13 cloud VM, Incus
  lts-6.0 from Zabbly with the key fingerprint checked, btrfs-progs, no API listener).

## Security review
| # | Finding | Resolution |
|---|---|---|
| V1 | Guest output is attacker-controlled once a tenant escapes into its own VM. | Output capped (8 MiB) and decoded into typed fields only; workspace IPs must be inside the VM's inner /24 before an edge route/port/ACL is written (`place.checkIP`). |
| V2 | A guest could report another tenant's workspace UUID to flip its state. | Console applies nested states only to rows of the same tenant (`recordNested`). hostd refuses non-`w-<uuid>` inner instances on delete. |
| V3 | Inner Incus API exposure. | No `core.https_address`; control only via the VM agent (vsock). Verified: inner bridge and VM address refuse :8443. |
| V4 | Inner containers privilege. | Inner project `ws`: `restricted=true`, privilege=isolated, nesting/lowlevel/interception/proxy/unix/gpu/usb/pci blocked, no VMs, `security.idmap.isolated=true`. |
| V5 | LLMNR responder on the tenant net (5355/tcp+udp, all addresses). | Disabled by `shippin-tvm-init` (resolved drop-in). |
| V6 | Guest MTU 1500 on a 1442 OVN network stalled TLS downloads. | `UseMTU=yes` in the image + `MTUBytes` from the network's `bridge.mtu`. |
| V7 | Validation ran after the placement lookup in `Action`. | Host/action validation first, then placement (fail closed before touching Incus). |
| Open | Inner image cache (`/var/lib/shippin/images`) is never pruned. | Low; prune by fingerprints no longer aliased. |
| Open | VM RAM is not ballooned back; founder VM = 32 GiB. | Decision for the operator (sizes). |
| Open | Legacy → VM workspace migration is designed, not implemented. | Needs the operator's go-ahead. |
| Open | Rebuild, custom domains and firewall rules on nested workspaces share code with legacy but were not exercised live. | Next live pass. |
