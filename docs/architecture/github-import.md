# GitHub import (M3)

Import a repository (public or private) into a new project through the **Shippin GitHub App**.
The devspace clones it, and the user can push branches and open pull requests from inside the
devspace without pasting a personal token.

## Flow

1. An org owner or admin presses **Connect GitHub** (New project → GitHub). The console sends them to
   `/apps/<app_slug>/installations/new` with an HMAC-signed `state` (tenant, account, nonce,
   expiry; `github.state_minutes`).
2. On GitHub they install the App and pick repositories. GitHub returns to `/v1/github/setup` with
   `installation_id`, a one-time OAuth `code` (request user authorization during installation)
   and `state`. The console checks `state`, swaps `code` for a user token, confirms the installation is
   in that user's `/user/installations` (setup parameters are client-controlled), drops the
   token, and binds the installation to the tenant (`github_installations`; one tenant per
   installation).
3. `GET /v1/tenants/{t}/github/repos` lists repositories of the tenant's live installations;
   `POST /v1/tenants/{t}/github/import` checks that the installation belongs to the tenant and that
   GitHub lists the repo for it (IDOR guard), then creates the project, records `project_sources`
   and enqueues `project.import` → `workspace.create(repo github:owner/repo@branch)` → provision.
4. hostd writes an **installation token** narrowed to that one repository and
   `github.token_permissions` to `/run/shippin/git/token` (tmpfs, 0600, user dev) over stdin, before
   bootstrap. `shippin-ws-bootstrap` clones `https://github.com/owner/repo.git` with
   `--filter=blob:none` and checks out the branch. The system git credential helper
   (`shippin-git-cred`) answers only for github.com, using the token file; `gh` gets `GH_TOKEN` from
   the file each time it runs.
5. The console's reconciler (leader) re-pushes fresh tokens to running GitHub devspaces every
   `refresh_minutes` (tokens last 60 min), polls installations every `poll_minutes`, and applies
   webhooks (`installation` deleted/suspend/unsuspend, `installation_repositories` removed,
   `repository` renamed). Revoked sources stop getting tokens; the devspace keeps its clone.

## Security

- No secret is stored in the database. App credentials come only from the environment
  (`SHIPPIN_GITHUB_*` ← sops `github_*` via `deploy/console-container.sh`). The PEM key is passed as
  one-line base64.
- Webhooks are checked with HMAC-SHA256 (`X-Hub-Signature-256`, constant time), capped at 1 MiB and
  deduplicated by `X-GitHub-Delivery`.
- Tokens are per repository and short-lived, and they live only in tmpfs. A rebuilt or restarted devspace gets a new one.
  Commits carry the user's own git identity, but pushes authenticate as the App (`<slug>[bot]`).

## App settings (what `deploy/github/app-manifest.json` creates)

| Setting | Value |
|---|---|
| Homepage URL | `https://<console_host>` |
| Callback URL | `https://<console_host>/v1/github/callback` |
| Request user authorization (OAuth) during installation | on |
| Expire user authorization tokens | on (GitHub default) |
| Setup URL | `https://<console_host>/v1/github/setup`, **Redirect on update** on |
| Webhook | active, `https://<console_host>/v1/github/webhook`, secret generated by GitHub |
| Repository permissions | Contents: Read and write; Metadata: Read-only; Pull requests: Read and write; Workflows: Read and write |
| Subscribe to events | Repository (GitHub always delivers `installation` and `installation_repositories` to the App) |
| Where can it be installed | Any account |

`create-app.sh <org>` writes a page that posts this manifest to GitHub. `convert-manifest.sh
<code>` (run on Gold) swaps the one-time code for the credentials and writes them into sops,
printing only id/slug/owner. Then set `github.app_slug` to the printed slug.

Manual fallback (no manifest): Org settings → Developer settings → GitHub Apps → New GitHub App, fill in
the table above, then generate a client secret and a private key, and store them with
`sops set` as `github_client_id`, `github_client_secret`, `github_private_key`,
`github_webhook_secret` (and `github_app_id`).

## Rollout

`github.enabled=true` with `github.tenants` set to the first tenant(s), and `jobs.enabled=true` (import and token
refresh run in the job runner and reconciler). Then deploy the console with `KEEP_ENV=1 GITHUB_ENV=1`.
Migration 018 adds `github_installations`, `project_sources` and `github_deliveries`.
Rollback: set `github.enabled=false` (the routes answer 404 and nothing new gets tokens); the tables can stay.
